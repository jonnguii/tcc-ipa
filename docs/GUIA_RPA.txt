=== GUIA PARA O DESENVOLVEDOR DE RPA ===

--- PASSO 0: INSTALAR O UV ---
Este projeto usa o gerenciador `uv` em vez do `pip` ou `npm`.
1. Para Windows (PowerShell): `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`
2. Para Mac/Linux (Terminal): `curl -LsSf https://astral.sh/uv/install.sh | sh`
3. Feche e abra o terminal novamente para aplicar.
*(Aviso: Se instalou via `pip install uv` e o terminal não reconhece, é erro de PATH. Recomendo usar os comandos acima. Se insistir no pip, você terá que adicionar `python -m ` antes de qualquer comando uv deste guia).*

--- PASSO 1: PREPARAR O AMBIENTE ---
1. Configure o arquivo `.env` na raiz do projeto (use o `.env.example`). Preencha `SUPABASE_URL` e `SUPABASE_SERVICE_KEY` com as credenciais do banco, senão o ERP não liga.
2. Certifique-se de que o ERP simulado está rodando. 
   O terminal precisa estar com o comando rodando: `uv run uvicorn erp_sim.main:app --reload --port 8000`
3. Instale o Playwright rodando no terminal:
   `uv add playwright`
   `uv run playwright install chromium`

--- PASSO 2: GERAR O CÓDIGO COM O CODEGEN ---
O jeito mais fácil de começar não é digitando código do zero, mas sim deixando o Playwright gravar os seus cliques.
1. No terminal, rode:
   `uv run playwright codegen http://localhost:8000/pedidos/novo`
2. Vai abrir o navegador do ERP e uma janela "Playwright Inspector" ao lado.
3. No navegador, faça o processo de inserir um pedido normalmente:
   - Selecione um cliente.
   - Digite uma data.
   - Digite a referência externa.
   - Escolha um produto e coloque a quantidade.
   - Clique em Salvar.
4. O Inspector vai gerar o código Python correspondente a cada clique seu. Copie esse código gerado.

--- PASSO 3: COLAR E AJUSTAR NO bot.py ---
1. Abra o arquivo `rpa/bot.py`. Eu já deixei uma estrutura lá.
2. Cole o código gerado pelo Inspector na seção indicada (Passo 4).
3. Agora, substitua os valores "chumbados" que você digitou (ex: a data "10/10/2026" ou o ID do cliente) pelos valores que vêm dentro da variável `pedido` da função.
   Exemplo:
   Mude: `page.get_by_test_id("ped-data").fill("2026-10-10")`
   Para: `page.get_by_test_id("ped-data").fill(pedido["data_entrega"])`

--- PASSO 4: A LÓGICA DE DUPLICIDADE E RETORNO ---
Seu robô não pode duplicar pedidos se o servidor cair.
1. Antes de cadastrar, o robô vai abrir `http://localhost:8000/pedidos?ref=ID_DA_REFERENCIA`.
2. Se aparecer uma linha na tabela, significa que já foi lançado. O robô deve abortar e retornar o status "duplicado".
3. Se der certo a gravação normal, ele precisa ler a mensagem verde de sucesso na tela e retornar `status="sucesso"`.
4. Em qualquer caso, ele deve tirar um screenshot usando `page.screenshot(...)`. Tudo isso já tem dicas no `rpa/bot.py`!
